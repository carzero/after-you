# 플레이 검증 기록 · v0.3 당시 기준

이 문서의 수치와 시뮬레이션은 v0.3 당시 3스테이지 설정이다. v0.4의 무한 진행/하락/힌트 규칙과 온라인 검증은 ONLINE.md를 따른다.

현재 아트 v0.2를 사용해 반복 플레이·모바일 배치·접근성을 개선했다. 새 원화/음원/후속 챕터는 이 작업에 포함하지 않았다.

## 재현 가능한 자동 시뮬레이션

`npm run simulate` 또는 `npm run simulate -- --write`. 시드 1–300, 3스테이지 × 3정책 = 2,700라운드. 시간 간격 20ms, 입력 승인 사이 1,200ms 이상. JSON의 seconds 값은 힌트/회수 연출을 제외한 활성 게임 시간. 모든 정책에서 같은 게임 규칙/NPC 구현을 사용한다. 결과 원본은 `PLAYTEST_SIMULATION.json`.

| 스테이지 | 전체 경로 기억 성공 | 관찰 우선 성공 | 무작위 성공 | 관찰 우선 시간 종료 |
| --- | --- | --- | --- | --- |
| 1 · 8줄 | 300/300 | 58/300 | 3/300 | 52/300 |
| 2 · 10줄 | 300/300 | 33/300 | 0/300 | 48/300 |
| 3 · 12줄 | 300/300 | 8/300 | 0/300 | 39/300 |

- 전체 경로 기억: 시작 전 공개 힌트를 배열로 보관하고 그 경로를 입력. 컴퓨터의 완전 기억이며 사람의 기억력을 가정하지 않음.
- 관찰 우선: 공개 안전/붕괴 결과를 사용. 앞줄을 조사할 NPC가 남아 있으면 기다리고, 더 이상 없으면 무작위 도전. 비밀 경로/저장한 힌트를 읽지 않음.
- 무작위: 힌트/관찰을 모두 무시하고 매번 좌우 선택.

관찰 우선은 무작위 선택보다 성공이 늘지만, NPC가 일찍 탈락하면 남은 구간은 다시 추측해야 한다. NPC를 오래 기다리면 시간 종료도 발생한다. 이것은 정책 간 비교이며, 실사용자의 성공률 예측이 아니다. 모든 줄을 기억하는 입력은 제한시간 내에 전부 성공했고 입력 규칙의 랜덤 경로 문제는 관찰되지 않았다.

힌트 표시 길이에 따른 인간의 기억률, 실제 터치 속도, 재미/난이도와 ‘약 30초 플레이’는 **사람의 테스트가 필요**하다. 따라서 이 비교만으로 힌트·시간·NPC 수치를 변경하지 않았다. 평균 시간은 정책에 설정한 입력 간격의 영향이 크며 사람의 플레이 시간으로 사용하면 안 된다.

## 이번 개선과 확인

- 두 번째 추락부터 연출 건너뛰기 → 실패 결과만 표시, 다음 스테이지 해금 없음. 일시정지 중 숨김/작동 불가. 재시도 시 라운드와 회수 레이어 초기화.
- OS 및 게임의 움직임 줄이기 → 실제 회전/점프 과장에 반영, 실행 중 OS 설정 변경 반영.
- 세로 320×568/375×667/390×844, 가로 568×320/844×390 → 게임 화면 스크롤 없이 입력 버튼을 화면 안에 유지, 버튼 높이 44px 이상. 가로 화면에서는 긴 시작/결과 패널과 설정 창의 내부 스크롤을 허용.
- 기존 이동·착지·추락·아트 앞뒤 레이어·클리어·저장 복원을 함께 회귀 검증.

실제 iOS/Android 기기, 청음·진동, 터치 감각과 새로운 원화의 검증은 아직 수행하지 않았다. 다음 사람 테스트에서는 초회/3회차의 소요시간·실패 줄·힌트 기억 여부·NPC 대기 시간을 관찰하고 수치를 조정한다. 외부 분석 서비스나 사용자 데이터 전송은 추가하지 않았다.
