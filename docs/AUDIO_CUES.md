# 오디오 이벤트 · v0.2 적용 기록

실제 BGM·효과음·반응음 파일은 **미제공**. `src/audio.js`의 Web Audio 사인파와 8음 패턴은 자체 생성한 임시 합성음이며 최종 사운드가 아니다.

| 이벤트 | 시점 | 임시 처리 |
| --- | --- | --- |
| jump | 이동 입력 승인 시 | 360Hz |
| land_safe | 안전 착지 확정 시 | 560Hz |
| tile_crack | 위험 착지 확정 시 | 120Hz |
| fall | 균열 후 600ms | 85Hz |
| rescue | 균열 후 1400ms | 270Hz |
| finish | 성공/실패 1회 확정 | 740Hz, 구조음 직후에는 140ms 늦게 시작 |

이벤트 payload: `type`, `actor`(캐릭터 ID), `player`, 시뮬레이션 `time`; jump/land_safe/tile_crack에는 `row`, `side`; finish에는 `outcome`, `elapsed`. `drainEvents()`로 한 번만 소비한다. 라운드 재생성 시 이벤트 큐는 새로 생성된다.

- 사용자 출발/재개 터치로 오디오 활성화. 자동 재생 차단은 브라우저 정책에 따름.
- 배경음악과 효과음은 독립 옵션. 진동 기본 꺼짐, 플레이어 위험 착지 시 지원 기기에서만 60ms.
- 설정·일시정지·탭 숨김·재시도·결과 시 활성 oscillator를 모두 중단. 새 라운드에 이전 음이 남지 않음.
- 실제 오디오 전달 시 파일명/버전/출처·이용 조건/임시 여부/길이/루프 구간/큐·음량을 등록하고 이 매핑을 교체. 최종 파일 청음·루프 이음새·중복 재생 검증은 미실행.

## 아트 v0.2 반영 시 수정 (2026-11-15)

실제 음원은 이번 패키지에도 없음. 기존 이벤트 이름과 시뮬레이션 발생 시점은 유지했다. rescue/finish가 같은 시점에 도착하면 결과 전환이 기존 음들을 먼저 정리하고, 구조음 120ms를 재생한 뒤 결과음을 140ms 오프셋으로 예약한다. 결과 처리에서 구조음을 다시 중단하지 않는다. 예약도 AudioContext 노드로 관리하므로 재시도/일시정지/설정 변경 시 함께 중단된다. 관련 단위 테스트에서 구조음 길이와 결과음 예약 순서·무음·재시도 중단을 확인했다. 실제 스피커 청음은 별도 미실행.

v0.3의 연출 건너뛰기도 기존 rescue/finish 이벤트를 한 번씩 소비하며, 구조음과 결과음 예약 정책은 동일하다. 건너뛰기 전 중단된 낙하음/음악은 결과 진입에서 정리한다.

아트 v0.3: takeoff/landing/rescue PNG는 시각 효과만 추가한다. rescue 시각 시작 1050ms와 기존 오디오 이벤트 1400ms를 구분하며 오디오 이벤트·예약 순서·음원 설정은 변경하지 않았다. 실제 음원은 여전히 미제공.
