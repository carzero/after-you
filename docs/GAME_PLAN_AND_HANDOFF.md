## 1. 핵심 목표

구름 위 소원 접수처로 향하는 참가자들이 무너지는 다리를 건너는 모바일 세로형 코미디 게임이다. 좌우 선택은 즉시 이해할 만큼 단순하게 만들고, 캐릭터의 표정·몸짓·추락·반송 연출을 주요 매력으로 삼는다.

플레이 감정은 ‘저 녀석 먼저 보내볼까?’ → ‘아, 망했다’ → ‘한 번 더’로 이어진다. 작은 모바일 화면에서도 캐릭터와 발판을 읽을 수 있어야 하며, 실패도 캐릭터를 더 보고 싶은 경험으로 만든다.

복잡한 육성·장비·전투는 제외한다. 캐릭터 엔딩 수집과 개인 기록으로 반복 동기를 제공한다. 기존 작품의 의상·상징·무대 디자인은 사용하지 않고 독자적인 구름 세계와 캐릭터로 제작한다.

## 2. 이야기

### 시작

캐릭터들에게 황금빛 초대장이 도착한다.

> 축하합니다! 소원 접수 대상자로 선정되셨습니다.\n구름 위 접수처까지 방문하시면 소원을 하나 들어드립니다.\n※ 방문 접수만 가능합니다.

구름 정거장 건너편에는 소원 접수처가 보인다. 하지만 연결된 다리는 부실공사 상태다.

> 두 발판 중 하나는 안전합니다. 어느 쪽인지는 담당자도 모릅니다.\n양보하는 마음으로 이용해 주세요.

첫 발판이 떨어지고 모두 굳어 있는 순간, 비둘기가 손을 내민다. “먼저 가세요.”

### 실패와 재도전

다리 아래 구름 회수반이 추락자를 푹신한 구름으로 구조하고 출발점으로 반송한다. 감자는 가방을 붙든 채 상자에 담겨 돌아오고, 오리는 왕관이 먼저 도착한다. 비둘기는 날갯짓하다가 결국 회수된다. 결과 도장은 ‘재방문을 환영합니다’다. 죽음이나 잔혹한 표현은 없다.

비둘기의 비행 문제는 입구의 ‘소원 접수 구역 비행 금지’ 표지판으로 가볍게 설명한다.

### 챕터 구성

| 챕터 | 배경 | 사건·시각적 개그 |
| --- | --- | --- |
| 1. 구름 정거장 | 파스텔 구름, 공중섬 | 초대장을 든 참가자들이 서로 먼저 가라고 양보한다 |
| 2. 바람 우체국 | 편지 풍선, 우편함, 소포 | 배달되지 못한 소원 편지가 날아다니고 사연이 드러난다 |
| 3. 천둥 공사장 | 먹구름, 노란 작업등, 표지판 | 안전을 강조하는 직원 옆에서 안전 표지판이 떨어진다 |
| 4. 별빛 대기실 | 남보라 하늘, 별자리, 번호표 | 접수처는 가까운데 대기번호는 줄지 않는다 |
| 5. 소원 접수처 | 황금빛 구름, 창구, 도장 | 소원이 이루어지고 캐릭터별 반전 엔딩이 열린다 |

전체 목표는 5챕터 × 5스테이지 = 25개다. 첫 구현 범위는 1챕터 3스테이지다. 이야기 전달은 짧은 입장 장면·표정·행동·엔딩 중심이며 긴 대화창은 지양한다.

## 3. 기본 플레이

| 항목 | 초기 제안 |
| --- | --- |
| 화면 | 모바일 세로, 페이지 스크롤 없는 한 화면 |
| 입력 | 왼쪽·오른쪽 버튼으로 다음 줄 선택 |
| 발판 | 줄마다 두 칸 중 하나만 안전 |
| 경로 생성 | 라운드 시작 때 확정, 진행 도중 변경 금지 |
| 힌트 | 시작 전에 안전 경로를 잠깐 표시 |
| 참가자 | 플레이어 1명 + NPC 3명 |
| 길이 | 첫 스테이지 8줄을 출발점으로 검증 |
| 제한시간 | 30~45초 범위에서 스테이지별 검증 |
| 성공 | 제한시간 안에 도착 |
| 실패 | 추락 또는 시간 종료 |
| 재시도 | 짧은 연출 후 한 번의 터치 |

안전하다고 확인된 발판은 이후에도 안전하다. NPC가 확인한 결과는 플레이어도 관찰할 수 있다. 플레이어의 선택에 맞춰 정답을 바꾸지 않는다.

NPC는 숨겨진 정답을 읽지 않고 관찰 결과와 성격에 따라 행동한다. 망설임 시간·도전 성향·따라가는 속도로 성격을 구분한다. 실제 밀치기와 물리 충돌로 타인을 추락시키는 기능은 초기 범위에서 제외한다. 밀치는 모습은 출발 전 개그로만 사용할 수 있다.

동시 이동, 일시정지, 시간 종료와 도착이 겹치는 경우의 판정은 Codex가 명시적으로 설계하고 검증한다. 이동 애니메이션 중 중복 입력으로 여러 칸이 처리되지 않도록 한다.

## 4. 캐릭터 설정

| ID | 캐릭터 | 외형 | 대표 행동 | 소원과 엔딩 |
| --- | --- | --- | --- | --- |
| potato | 직장인 감자 | 점박이 감자 몸, 흰 셔츠, 파란 넥타이, 갈색 가방·구두 | 넥타이를 만지며 눈치 보기, 추락해도 가방은 유지 | 출근 없이 월급 받기 → 구름 다리 민원 재택근무 |
| pigeon | 넥타이 비둘기 | 회색 몸, 밝은 배, 흰 칼라, 빨간 넥타이, 짧은 주황 발 | 정중히 양보하고 안전하면 따라가기 | 사람들이 피하지 않기 → 인기 조형물로 오해받음 |
| duck | 왕관 오리 | 노란 몸, 주황 부리·발, 작은 금관 | 품위 있게 나섰다가 물러남 | 진짜 왕 → 고무 오리 왕국의 왕 |
| rabbit | 근육 토끼 | 흰 거대 상체, 긴 귀, 짧은 다리, 짙은 반바지 | 거창한 준비운동, 작은 점프 | 긴 다리 → 첫걸음에 다리가 꼬임 |

보조 인물은 친절한 무표정 구름 안내 직원과 헬멧을 쓴 구름 회수반이다.

감자 엔딩 예시: 재택근무 책상에서 커피를 마시는 감자에게 전화가 온다. “감자님, 다리 민원 들어왔습니다.”

캐릭터 성능은 초기에는 동일하게 한다. 첫 챕터 완료 후 나머지 주연을 선택할 수 있도록 제안한다. 차이는 표정·모션·소리·엔딩에 둔다.

## 5. 아트 방향과 화면

말랑한 클레이·비닐 장난감 같은 입체 질감, 둥근 실루엣, 큰 눈과 짧은 팔다리를 유지한다. 배경은 크림·민트·살구·라벤더 중심이며 캐릭터가 묻히지 않게 대비를 확보한다.

입체감 있는 2D 원화를 캐릭터·다리·구름 레이어로 분리하여 구현하는 방식을 제안한다. 실제 3D 모델은 현재 제작물에 포함되지 않는다.

첫 분위기 시안은 홍보용에 가까운 큰 캐릭터 구도다. 실제 게임에서는 상단 제목을 축소하고 다음 3~4줄이 잘 보이도록 캐릭터 크기를 조정한다. 카메라는 전진을 따라가고 주요 반응 때 캐릭터가 고개를 돌려 표정을 보여준다.

### 아트 제작 목록

| 분류 | 구성 |
| --- | --- |
| 타이틀 | 로고, 대표 배경, 주연, 시작 버튼 |
| 챕터 배경 | 하늘, 먼 공중섬, 앞·뒤 구름, 챕터별 장식 |
| 다리 | 출발대, 도착대, 발판, 기둥, 난간 |
| 발판 상태 | 정상, 확인된 안전 표시, 균열, 붕괴 파편 |
| 소품 | 표지판, 우편함, 편지, 공사등, 번호표, 접수 창구 |
| 결과 | 성공·실패 패널, 접수 도장, 반송 상자 |
| 선택 화면 | 캐릭터 초상, 소원 카드, 잠금·해금 표시 |
| 이야기 | 초대장, 챕터 입장 컷, 캐릭터별 엔딩 |
| 설정 | 음악·효과음·진동·화면 흔들림 아이콘 |
| 홍보 | 앱 아이콘, 소개 이미지, 예고 영상용 소재 |

### 캐릭터별 원화·동작

| 묶음 | 필수 내용 |
| --- | --- |
| 기준화 | 정면, 후면, 측면, 게임용 3/4 방향 |
| 대기 | 호흡, 눈 깜빡임, 눈치 보기 |
| 이동 | 발 들기, 도약, 공중, 착지 |
| 판단 | 발끝 확인, 먼저 가라는 손짓 |
| 안전 | 안도, 허세 |
| 위험 | 균열 감지, 아래 보기, 공중 정지 |
| 추락 | 허우적, 아래로 떨어짐 |
| 결과 | 구름 착지, 반송, 승리 |

점프·착지·추락은 실제 자세 변화가 있는 원화를 제작한다. 호흡·눈 깜빡임·소품 흔들림은 파츠를 분리해 움직일 수 있다. 정확한 프레임 수는 첫 동작 테스트 후 확정한다.

게임용 원화는 캐릭터별·동작별 개별 투명 PNG로 전달한다. 합본 시안은 참고용이며 게임용 파일을 대신하지 않는다. 얼굴·의상·비율·색·소품 위치를 일관되게 유지한다. 효과 기호와 그림자는 가능하면 별도 레이어로 둔다.

고해상도 원본과 실행용 최적화본을 분리한다. 문구는 그림에 합치지 않고 코드로 표시하여 수정·번역할 수 있게 한다.

## 6. 사운드

가볍고 진지하게 출발하다가 악기 소리가 삐끗하는 코미디 분위기다. 피치카토 현악기·목관·목금·작은 타악기를 중심으로 한다.

| 종류 | 내용 |
| --- | --- |
| 타이틀 | 짧고 기억하기 쉬운 주제 |
| 기본 플레이 | 발걸음과 어울리는 가벼운 루프 |
| 챕터별 음악 | 동일 주제를 우체국·공사장·별빛 분위기로 변주 |
| 시간 부족 | 짧은 긴장 리듬 추가 |
| 성공 | 작은 팡파르와 우스운 마무리 |
| 실패 | 공중 정지 때 잠깐 비운 뒤 내려가는 음 |
| 엔딩 | 소원 성취 후 반전을 강조하는 선율 |

효과음: 발걸음, 도약, 착지, 균열, 붕괴, 바람, 구름 착지, 도장, 버튼, 해금. 반복 빈도가 높은 소리는 3~4개 변형을 제안한다.

캐릭터 반응음: 감자의 ‘어?’와 한숨, 비둘기의 낮은 구구 소리, 오리의 잘난 척하는 꽥과 당황한 꽥, 토끼의 힘주는 소리와 가는 비명. 긴 대사 녹음보다 비언어적 반응을 우선한다.

사운드는 현재 미제작이다. 실제 파일 제작 후 청음·루프 이음새·음량·중복 재생을 확인하고 출처와 이용 조건을 기록한다. 원본 WAV와 웹 재생용 압축본 제공을 목표로 하며 최종 포맷은 구현 환경에 맞춘다.

## 7. 특수효과와 타이밍

| 단계 | 초기 길이 | 연출 |
| --- | --- | --- |
| 이상 감지 | 0.15초 | 발판 흔들림과 작은 균열음 |
| 현실 부정 | 0.25초 | 발판은 사라지고 몸은 잠시 공중 유지 |
| 확인 | 0.20초 | 눈동자를 아래로, 음악 잠깐 비움 |
| 추락 | 0.45초 | 허우적, 소품은 한 박자 늦게 추락 |
| 구조 | 0.35초 | 구름이 꺼졌다가 튀어나옴 |

위 시간은 연출 초깃값이며 게임 테스트로 조정한다. 반복 실패 시 연출 단축·건너뛰기를 제공한다.

추가 효과: 안전 착지 먼지와 눌림, 땀방울과 무릎 떨림, 추락 속도선과 소품 회전, 구름 속 실루엣, 성공 꽃가루와 도장, 배경의 느린 구름·편지·별.

경로를 읽기 어렵게 하는 번쩍임과 큰 흔들림은 피한다. 화면 흔들림·진동 감소 또는 끄기 옵션을 제공한다.

## 9. 진행·저장·초기 제외 범위

저장 대상은 해금한 챕터·캐릭터·엔딩, 개인 최고 기록, 오디오·진동·화면 설정이다. 저장 버전 관리와 손상 시 복구 처리, 재실행 후 복원은 Codex에서 구현한다.

첫 버전에서 광고·결제·온라인 대전·장비·일일 미션은 제외한다. 외부 서버나 API가 필수인 구조로 시작하지 않는다. 기존 다른 게임의 Worker·API·사용자 데이터를 변경하지 않는다.

Windows/MSIX 제작은 현재 요청 범위에 포함되지 않는다. 추후 요청되면 별도 패키징 기준을 적용한다.

## 10. 제작 순서와 검증

| 단계 | 결과 | 검증 |
| --- | --- | --- |
| 1 | 주연 디자인·실제 화면 구도 | 작은 화면의 표정·실루엣·발판 가독성 |
| 2 | 감자·비둘기 모션, 1챕터 배경·발판·기본 소리 | 이동·관찰·추락·재시도 |
| 3 | 오리·토끼 모션, 회수반, 캐릭터별 실패 | 반복해도 지루하지 않은 반응 |
| 4 | 나머지 챕터·음악 변주·엔딩 | 시각적 변화·진행 동기 |
| 5 | 아이콘·소개 이미지·최종 인계 | 로딩·음량·저장·재실행·모바일 호환 |

첫 목표는 ‘감자와 비둘기가 눈치를 보다가 한 명이 떨어지고 반송되는 약 30초 플레이’다. 이 장면을 아트·시스템·사운드의 통합 기준으로 삼는다.

필수 검증:

- 안전 경로가 플레이 도중 바뀌지 않는다.
- 확인된 안전 발판은 재사용 가능하다.
- NPC가 숨겨진 정답을 참조하지 않는다.
- 연타·동시 이동·시간 종료 상황에서 판정이 중복되지 않는다.
- 배경으로 앱을 보냈다가 돌아올 때 타이머·소리 정책이 일관된다.
- 재시도 후 이전 라운드의 상태·효과음이 남지 않는다.
- 무음과 감소 효과 설정이 저장된다.
- 작은 화면에서 발판과 버튼이 가려지지 않는다.
- 신규 아트 반영 후 기존 이동·판정·저장을 회귀 검증한다.

## 12. Codex 시작 지시문

이 문서를 기준으로 모바일 세로형 게임 ‘먼저 가세요’의 시스템을 구성한다. 아트·사운드는 별도 제작 중이므로 누락된 소재를 최종 완성본으로 표시하지 않는다. 우선 1챕터 3스테이지에 필요한 경로 생성·좌우 이동·NPC 관찰 행동·추락·재시도·진행 저장을 구현한다. 이벤트와 아트 기준점을 분리해 새 소재를 교체하기 쉽게 만든다. 첫 목표는 감자와 비둘기의 약 30초 플레이다. 판정은 고정된 경로에 따르고 코미디 연출 때문에 규칙을 변경하지 않는다. 임시 소재는 명확히 구분하고 전달된 원화 디자인을 임의로 바꾸지 않는다. 완료·미완료·검증 결과와 다음 작업은 HANDOFF.md에 갱신한다.
