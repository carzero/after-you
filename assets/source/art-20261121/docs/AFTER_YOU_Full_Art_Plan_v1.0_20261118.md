# 먼저 가세요 · 전체 아트 검토 및 제작 계획 v1.0

작성: 2026-11-18 · CARZERO STUDIO
대상: 모바일 세로형 게임, 1챕터 3스테이지 우선 / 전체 5챕터 25스테이지 목표
성격: 제작 계획. 아래 신규 원화·화면·규격 제안은 제작 완료를 뜻하지 않는다.

## 1. 검토 결론

캐릭터 4명의 7포즈 시안은 존재하지만, 게임 전체 아트가 완성된 상태는 아니다. 현재 43개 PNG는 캐릭터 28장, 환경 4장, 구조 관련 6장, 콘셉트 2장, 효과 3장이다. 구조 상자 수정본처럼 대안 이미지도 포함하므로 43장을 서로 다른 완성 기능 43개로 계산하지 않는다. 전체 아트 완성률을 파일 수로 환산하지 않는다.

현재 가장 큰 공백은 타이틀 전용 구성, 실제 게임 배경 레이어, 출발·도착대, UI 아이콘과 상태 표현, 캐릭터 선택·스테이지 선택·결과 화면이다. 새 캐릭터를 늘리기보다 기존 캐릭터 정리와 1챕터의 완결된 화면 흐름 제작을 우선한다.

검토 근거: 전체 기획 및 Codex 인계서 v0.1, 아트 인계 v0.3의 HANDOFF와 ASSET_MANIFEST, 사용자 제공 시스템·오디오 규약. 이번 검토는 문서·자산 목록 대조이며 실제 최신 게임 화면, 저장소 코드, 전 원화 픽셀 재검수는 수행하지 않았다. 기존 인계서의 번짐·디자인 불일치 사항을 제작 과제로 승계한다.

## 2. 공통 아트 기준

- 방향: 말랑한 클레이·비닐 장난감 질감, 둥근 실루엣, 따뜻한 좌상단 조명, 크림·민트·살구·라벤더.
- 감정: 정중한 양보와 눈치 보기, 실패해도 다치지 않는 구조·반송 코미디.
- 캐릭터: 감자 셔츠·파란 넥타이·가방, 비둘기 빨간 넥타이, 오리 왕관, 근육 토끼 비율을 유지한다.
- 플레이 배경은 낮은 대비, 캐릭터·발판은 높은 구분도. 구름 장식이 다음 발판을 가리지 않는다.
- 조작·설정용 작은 아이콘은 입체 질감을 줄인 단순 벡터. 큰 소품·대표 일러스트는 클레이 원화.
- 제목·버튼·번호·설명·도장 문구는 텍스트 레이어로 분리한다. 이미지 안에 문구를 구워 넣지 않는다.
- 색만으로 상태를 구분하지 않는다. 안전은 체크·테두리, 잠금은 자물쇠, 선택은 명확한 선택 표시를 병행한다.
- 모바일 가독성을 먼저 확정한 후 고해상도 원화를 제작한다. 복잡한 난간과 기둥은 필수 소재로 고정하지 않고 화면 가림 여부에 따라 생략한다.

## 5. 배경과 무대 자산

모든 챕터는 공통 카메라·발판 원근을 유지한다. 25개 스테이지에 배경 25장을 각각 새로 만들지 않고, 챕터별 레이어와 장식 조합으로 변주한다. 1챕터는 현재 구현된 3개만 우선 검수한다.

### 챕터별 공통 납품 단위

1. 하늘 1장: 세로 배경, 중앙 이동 경로가 비어 있는 구성.
2. 원경 랜드마크 1장: 접수처로 향하는 목표 방향을 보여 주는 투명 레이어.
3. 뒤 구름 세트 1묶음: 가장자리 배치용 독립 오브젝트 3종.
4. 앞 구름 세트 1묶음: 화면 하단·측면용 2종, 발판 가림 제한.
5. 출발대·도착대 각 1장: 공통 접지 시점과 부착점.
6. 정상 발판·균열 오버레이·파편 세트: 공통 형태를 유지하고 재질/색만 제한적으로 변주.
7. 대표 장식 3종: 각 챕터 이야기용. 필요 없는 장식은 추가하지 않는다.

묶음 수는 파일 수가 아니다. 파편·마스크·반복 타일·모션 분리 후 실제 파일 수를 확정한다.

| 챕터 | 색/분위기 | 랜드마크·장식 | 변주와 검수 |
| --- | --- | --- | --- |
| 1 구름 정거장 | 민트·크림·살구, 맑은 아침 | 작은 접수처, 안내 표지, 비행 금지 표지, 초대장 | 기존 하늘·접수처 활용 후보. 출발/도착대와 앞뒤 구름 신규 |
| 2 바람 우체국 | 연하늘·살구, 느린 바람 | 우체국, 우편함, 봉투, 편지 풍선 | 움직이는 편지는 측면만. 다리 중앙을 가로지르지 않음 |

## 6. 아이콘 및 공통 UI

기본 도안 24종을 계획한다. 켜짐/꺼짐·선택·비활성 상태는 별도 도안 수에 중복 산입하지 않는다. 가능한 경우 동일 벡터와 코드 스타일로 파생한다.

| 그룹 | 기본 도안 | 수 |
| --- | --- | --- |
| 이동/메뉴 | 왼쪽, 오른쪽, 시작/재개, 일시정지, 다시하기, 홈, 뒤로, 닫기, 설정 | 9 |
| 설정 | 음악, 효과음, 진동, 움직임 줄이기 | 4 |
| 진행/HUD | 시간, 도착 깃발, 안전 체크, 잠금, 해금, 챕터 완료 인장 | 6 |
| 안내/수집 | 초대장, 소원, 정보, 경고, 기록 트로피 | 5 |

아이콘은 24px/32px 표시에서 알아볼 수 있는 단순 실루엣으로 제작한다. 원본은 SVG 권장, 필요한 PNG 파생본을 함께 제공한다. 아이콘 시각 크기와 터치 영역은 구분하며 버튼 터치 영역은 44 CSS px 이상을 목표로 한다.

공통 UI 부품: 기본/강조 버튼, 둥근 패널, 모달 패널, 말풍선, 소원 카드, 챕터 카드, 진행 표시 바, 토글, 도장 바탕, 선택 테두리. 버튼은 기본·눌림·비활성·키보드 포커스, 토글은 켜짐·꺼짐, 카드와 노드는 기본·현재·완료·잠금 상태를 정의한다. 텍스트를 포함한 화면은 색 대비를 검수하고 글자 길이 증가에도 잘리지 않게 한다.

실행 화면에 쓰는 설정은 현재 시스템과 맞춘다. 별도의 화면 흔들림 설정을 새로 강제하지 않고 움직임 줄이기에 연결한다. 음악·효과음·진동 설정은 각각 독립 표시한다.

## 7. 캐릭터·보조 인물 보완

현재 28포즈는 유지·보정 대상이며 다시 28개 신규 생성으로 계산하지 않는다.

| 작업 | 수량/단위 | 우선순위 | 완료 기준 |
| --- | --- | --- | --- |
| 기존 포즈 외곽/디자인/기준점 정리 | 28장 | P0 | 배경 3색에서 깨끗한 경계, 공통 몸 크기, 등록 기준점 |
| 제작 기준화 | 4인 각 정면·측면·후면·3/4 | P2 | 이후 원화의 의상·소품·비율 기준으로 사용 |
| 선택 화면 초상 | 4종 | P1 | 동일 머리 크기와 시선 높이, 48px에서도 구분 |
| 눈치 보기/먼저 가세요/안도 | 4인 × 3포즈 = 12종 제안 | P2 | 성격이 드러나고 기존 7포즈와 디자인 일치 |
| 눈 깜빡임·호흡 | 4인별 파츠 또는 최소 프레임 | P2 | 프레임 수는 재생 테스트 후 확정 |
| 안내 직원/회수반 | 역할 2종 | P1/P2 | 기존 worker는 후보, 역할 구분 확인 후 필요한 쪽 제작 |
| 캐릭터별 반송 개그 | 4개 연출 묶음 | P2 | 감자 가방, 비둘기 날갯짓, 오리 왕관, 토끼 상자 비율 개그 |

오리 jump 치아 표현은 기준 부리와 통일하고, 토끼 fall은 회전 여백을 확보한다. 공중 포즈에 발바닥 bbox를 강제 정렬하지 않고 가상 접지점과 몸통 기준으로 정렬한다. 단일 포즈를 확대·회전한 것만으로 전용 모션 프레임 제작 완료라 부르지 않는다.

앱 아이콘은 네 캐릭터를 모두 작게 넣지 않고 작은 크기에서 한눈에 읽히는 대표 모티브로 제작한다. 타이틀 로고와 앱 아이콘은 용도가 달라 별도 구성한다. 플랫폼별 제출 크기는 배포 대상 확정 때 해당 규격을 확인한다. 현재는 1024×1024 마스터를 목표로 한다.

홍보용 장면을 실제 플레이 화면처럼 표시하지 않는다. 음원 제작은 본 아트 계획의 범위 밖이며, 효과 시점은 AUDIO_CUES와 연동하도록 인계한다.

## 9. 파일·레이어·표시 규격 제안

| 자산 | 원본 목표 | 실행 전달 | 필수 메타데이터 |
| --- | --- | --- | --- |
| 캐릭터 | 개별 투명 PNG, 긴 변 1024px 이상 | 원본 + 표시 크기에 맞춘 경량본 | 시점, 공통 배율, 접지/몸통 기준점, 포즈 순서·시간 |
| 배경 하늘 | 1440×2560 이상 목표 | 크롭/반복 방식에 따른 경량본 | 카메라 범위, 가장자리 여유, 불투명 여부 |
| 배경 오브젝트 | 개별 투명 PNG | 필요 해상도별 파생본 | 레이어, 원근, 반복/스크롤 계수 |
| UI 아이콘 | 벡터 SVG | SVG 또는 PNG | viewBox, 표시 크기, 상태, 접근성 라벨 |
| 패널/버튼 | 확장 가능한 도안 | CSS/벡터/9-slice 중 적합한 방식 | 모서리, 내부 패딩, 텍스트 안전영역 |
| 이야기/엔딩 | 세로 원화 | 화면 비율별 크롭 가능한 파생본 | 얼굴·문구 안전영역, 원본 버전 |
| 효과 | 개별 투명 원화/필요 프레임 | 분리 효과 레이어 | 시작 이벤트, 시간, 반복, reduced-motion 대체 |

위 해상도는 계획값이며 기존 원본 해상도를 거짓으로 바꾸거나 확대만으로 고품질 원본으로 판정하지 않는다. PNG 원본을 보존하고 투명 WebP 등 실행 형식은 실제 브라우저·메모리 검수 후 확정한다. 전체 5챕터 원화를 시작 시 한꺼번에 로드하지 않는다.

파일 경로는 assets/characters/{id}, backgrounds/ch01~ch05, bridge, props, ui/icons, ui/panels, vfx, story, branding으로 통일한다. 현재 environment와 rescue 경로는 다음 인계에서 이전→새 경로 매핑을 제공하고 코드 참조를 함께 교체한다.

명명 예: ch01_cloud_front_01_v001.png. 상태값은 draft → art_reviewed → runtime_ready → integrated_verified. 검수 근거 없이 다음 상태로 올리지 않는다. 발바닥 기준점 미측정값은 null로 유지하며 임의의 중심값을 측정값으로 기록하지 않는다.

## 10. 단계별 실행 순서와 인수 기준

| 단계 | 제작 작업 | 전달물 | 다음 단계 진입 기준 |
| --- | --- | --- | --- |
| P0 플레이 한 화면 완성 | 28포즈 보정, 1챕터 배경 레이어·출발/도착대·발판·구조·기본 효과 | 플레이 아트 묶음, 실측 기준점, 레이어 명세 | 320×568에서 다음 발판·얼굴·입력이 보이고 420ms 이동/1400ms 실패 연출과 일치 |
| P1 1챕터 전체 UX | 타이틀, 24 아이콘, 선택/설정/결과/초대장/해금 화면 | 화면별 시안, 공통 UI 묶음, 앱 아이콘 초안 | 타이틀→선택→플레이→결과→재시도 흐름에서 임시 그래픽 누락 없음 |
| P2 캐릭터 연기 강화 | 기준화, 판단 12포즈, 대기 파츠, 캐릭터별 반송 개그 | 모션 명세와 추가 원화 | 작은 화면에서 행동이 구분되고 반복 실패를 지연시키지 않음 |
| P3 전체 콘텐츠 확장 | 챕터 2–5 배경/소품, 입장 컷, 4인 엔딩 | 챕터별 묶음, 엔딩 묶음 | 챕터 식별성과 공통 발판 가독성 유지, 실제 구현 범위와 분리 표기 |
| P4 출시 아트 정리 | 로고·아이콘 최종, 홍보물, 경량화·권리 기록 | 최종 마스터/실행본/목록 | 실기기·재실행·배포 포맷 검수, 사용 출처와 조건 등록 |

P0와 P1이 끝나면 1챕터의 화면 흐름을 처음부터 끝까지 검수할 수 있다. 이를 전체 25스테이지 아트 완성으로 보고하지 않는다. 제작 일정은 생성 횟수로 추정하지 않고 각 단계의 보정·통합 검수 후 갱신한다.

### 바로 다음 제작 묶음

1. 실제 플레이 화면 레이아웃 시안 1종: 캐릭터/발판 크기·카메라·HUD 영역부터 고정.
2. 1챕터 출발대·도착대 2종과 앞뒤 구름 5종: 정상/균열 발판과 같은 원근 유지.
3. 캐릭터·기본 효과 경계 보정 및 기준점 등록: 신규 자산과 함께 읽히는지 확인.
4. 타이틀 전용 시안과 기본 아이콘 스타일 샘플 6종: 좌우·설정·시간·체크·잠금부터 통일.
5. 스타일 확인 후 24아이콘 전체와 선택/결과/설정 화면으로 확장.

이는 실행 순서 제안이며 매 이미지마다 별도 승인을 요구하는 절차가 아니다. 기존 승인 방향 안에서 제작·수정·검수를 이어간다.

## 11. 최종 검수 체크리스트

- 원화: 검정·흰색·민트 배경에서 외곽 번짐, 잘림, 반투명 잔재 확인.
- 캐릭터: 얼굴·넥타이·왕관·가방 위치와 신체 비율 일치, 포즈 전환 크기 흔들림 확인.
- 플레이: 비공개 정답 누설 없음, 안전/붕괴 관찰 이후에만 상태 이미지 변경.
- 화면: 320×568, 360×800, 390×844에서 한 화면 구성·안전영역·글자 확대 점검.
- 가림: NPC 겹침·토끼 귀·추락 효과·전경 구름이 다음 발판이나 버튼을 숨기지 않음.
- 움직임: 이동 420ms, 실패 1400ms 유지. 설정/탭 숨김 시 효과도 정지, 감소 모드 대체 제공.
- 결과: 추락과 시간 종료 구별, 성공/해금/챕터 준비 중 표시가 실제 상태와 일치.
- UI: 작은 아이콘 식별, 상태를 색 외 형태로 구별, 텍스트 분리, 버튼 터치 영역 확보.
- 통합: 이동·추락·재시도·설정·진행 저장 회귀 검증. 기존 테스트 통과 기록을 새 아트 검증으로 재사용하지 않음.
- 성능: 최초 로딩 용량, 이미지 디코딩·메모리, 모바일 Safari/Android 실기기 확인.
- 전달: 파일 존재·해시·해상도·알파·기준점·레이어·버전·완성 상태·출처 조건 기록.

아트 제작 담당은 이미지·규약·보정 목록을 제공하고, Codex는 로딩·렌더링·애니메이션·이벤트 연결과 회귀 검증을 맡는다. 새 아트 적용으로 게임 규칙이나 기존 데이터 구조를 임의 변경하지 않는다.
